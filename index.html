五个 Hook 一张表看懂

Hook返回值变化时是否触发渲染典型场景
useState[value, setValue]是计数器、表单输入、开关、列表数据
useEffect无（可返回一个清理函数）取决于副作用做了什么请求数据、订阅、定时器、事件监听、手动改 DOM
useContextProvider 提供的值是（Provider value 变化时）主题、登录用户、语言偏好
useMemo缓存的计算结果否（它本身只返回值）昂贵计算、稳定的对象引用
useRef{ current }否DOM 引用、timer id、上一次的值
🔑 Hooks 的两条规则
① 只能在组件 / Hook 的顶层调用，不能放进 if、循环或嵌套函数里；② 只能在函数组件或自定义 Hook 中调用。 所谓自定义 Hook，就是名字以 use 开头、内部会调用其他 Hook 的普通函数。

2useState：让函数组件拥有状态

Hooks 出现之前，只有 class 组件能持有 state。useState 让函数组件也能保存并更新数据： 它的值在多次渲染之间被保留，变化时触发重新渲染。

基本用法

  • useState(0)：初始值为 0，返回数组 [值, 修改函数]
  • setCount：唯一合法的更新方式，直接给 count 赋值无效
  • 点击按钮 → 调用 setCount(count + 1) → 组件重新渲染 → 界面显示新数字

存储对象类型

🔑 更新对象 / 数组要「展开 + 覆盖」
{ ...user, age: user.age + 1 } 先复制原对象再覆盖 age。 直接写 user.age = 26 不会触发渲染，因为对象引用没变。
💡 连续多次更新用函数式写法
setCount(c => c + 1) 拿到的必定是最新值； 而 setCount(count + 1) 里的 count 是本轮渲染的快照，连续调用两次只会 +1。

练习：NameForm

任务：写一个 NameForm 组件 —— 用 useState 保存输入的名字，页面上有输入框和按钮， 点击按钮后显示 Hello, John! 这样的问候语。

📘 参考答案：NameForm

小结

  • useState 让函数组件拥有状态，可以存任意类型的值
  • 永远用 setter 更新状态，不要直接赋值
  • 对象 / 数组要产生新引用才会触发渲染

Step 00 · 页面是怎么加载 React 的

目标：项目在 Chrome 里跑起来，并知道每个 <script> 标签在干什么。

  • 前两个标签从 CDN 加载 React 与 ReactDOM，挂成全局变量 React、ReactDOM
  • 第三个加载 Babel，负责在浏览器里把 JSX 翻译成普通 JS
  • 第四个是你的代码；type="text/babel" 让浏览器先别执行，等 Babel 翻译完再跑
  • 文件第一行 const { useState } = React;，在 Vite 项目里写作 import { useState } from "react";——其余完全一样
⚠️ 为什么必须用 Live Server，不能双击打开
Babel 要用网络请求去取 app.js；用 file://… 直接打开的页面不允许这么做，结果就是一片空白。 请在 VS Code 里右键 index.html → Open with Live Server（端口 5501），并保持 Console 常开。

Step 01 · 第一个 state 变量

把 index.html 最后一个 script 换成 ./app-cdn.js，打开只有一个按钮的迷你计数器：

  • useState(0)：向 React 要一份从 0 开始的 state
  • React 返回两项数组：当前值 + 修改它的 setter
  • 左边的方括号是数组解构，名字随你起，约定是 thing / setThing
  • 点击并不是直接改 count，而是调用 setCount 告诉 React：存新值，然后重新调用 Counter()
🔑 渲染循环一句话
你调用 setter → React 存下新值 → React 再次调用你的组件 → 返回的 JSX 用上新值 → React 只更新页面上真正变了的那一小块。 第二次渲染时 useState(0) 里的 0 会被忽略，返回的是存起来的值。

Step 02 · 为什么普通变量不够用

把 Counter 换成这个「无 hook」版本，点三下看控制台：

  • 控制台里变量确实变成 1、2、3，但页面依旧写着 You clicked 0 times
  • Counter rendered 只出现一次 —— 改普通变量没有通知 React，React 就不会再调用组件
  • 就算它重新调用，let count = 0 也会从头再来

现在每点一次，控制台就多一行 Counter rendered, count = 新值。

🔑 state 就是「React 替你记住的东西」
值存在你的函数之外、两次调用之间。setter 是唯一能改它的方式，因为调用 setter 才是「通知 React 重新渲染」的动作。

Step 03 · 三个按钮与 updater 函数

把 script 换回 app.js，读这三个 handler：

  • Reset 传值：「把它设成 0」，新值与旧值无关
  • Increment / Decrement 传 updater 函数：「拿当前值加 1」；React 会把最新值作为 c 传进去（写 prev 也很常见）
🚨 别写成 onClick={setCount(0)}
那样 setter 会在渲染过程中执行 → 触发新的渲染 → 又执行 → React 抛 Too many re-renders，页面变白。 必须用箭头函数包一层：onClick={() => setCount(0)}。

Step 04 · 传值，还是传 updater？

实验：加一个 +3 按钮，连续三次传值：

改成 updater 形式，结果才是 +3：

💡 快照 + 批处理
  • 一次渲染里 count 是个固定的快照：如果点击时它是 0，三行都等于「把它设成 1」
  • updater 会被排队执行，每一个拿到前一个的结果，所以是 3
  • 点一次 +3，控制台只多一行 App rendered：React 把一次事件里的多次更新批处理成一次渲染
  • 经验法则：新值由旧值算出来 → 用 updater；固定值 → 直接传值

Step 06 · Lifting state up（状态提升）

打开 lifting-state.html，同一个计数器被拆成三层嵌套的组件，每个色块就是一个组件：

组件有 state 吗拿到什么 props负责什么
App（父）有：count无拥有 count，创建三个 callback
Counter（子）无count + 三个 callback显示 count，把 callback 继续往下传
Controls（孙）无三个 callback按钮触发这些 callback
🔑 状态提升
按钮在 Controls 里，数字显示在 App 和 Counter 里， 所以 state 必须放在需要它的所有组件的最近公共父级 —— 这里是 App。这就是 lifting state up。 数据以 props 向下流，点击事件以 callback 向上回报。

跟着一次点击走一遍：App 创建 onIncrement={() => setCount((c) => c + 1)} 传给 Counter → Counter 不用它，只往下转发 → Controls 把它挂到按钮上 → 点击后函数在 App 里执行，App 的 state 变化，整棵树带着新 count 重渲染。

💡 用 DevTools 看一眼
打开 React Developer Tools 的 ⚛ Components 标签：点 App 能看到 hooks 里的 State: 0； 点 Counter / Controls 只有 props。点按钮，看 App 的 state 变化。
THINK（1 分钟）：如果把 useState 挪进 Controls 会坏在哪？ 按钮照样能用，但 App 和 Counter 显示不出 count 了 —— 父组件读不到子组件的 state，数据只向下流。

Step 08 · 规则、数组与对象、挑战和自检

Hooks 的两条规则

  1. 只在组件的顶层调用 hook，不能放进 if、循环或嵌套函数 —— React 靠调用顺序区分各个 useState，顺序必须每次渲染都一致
  2. 只在 React 组件（或你自己的自定义 hook）里调用，不要在普通 JS 函数里调用

数组与对象：不要原地修改

不要这样要这样
list.push(item)setList((l) => [...l, item])
user.age = 26setUser((u) => ({ ...u, age: 26 }))
list.splice(i, 1)setList((l) => l.filter((_, j) => j !== i))

React 靠比较新旧值来决定要不要重渲染；原地改同一个数组，它还是同一个引用，React 可能察觉不到。

4useEffect：处理副作用

useEffect 用来在函数组件里执行副作用：请求数据、订阅、定时器、手动改 DOM。 它相当于 class 组件中 componentDidMount + componentDidUpdate + componentWillUnmount 三者的合体。

基本用法：定时器 + 清理

  • 第一个参数：包含副作用逻辑的函数
  • 第二个参数：依赖数组 []
  • 返回的清理函数：组件卸载时、或 effect 再次运行前执行

依赖数组的四种写法

写法执行时机用途
useEffect(fn)每次渲染之后极少用，容易出 bug
useEffect(fn, [])只在挂载后一次（卸载时清理）初始化请求、添加全局监听
useEffect(fn, [dep])挂载时 + dep 变化时参数变了重新请求数据
useEffect + return 清理挂载 → 清理 → 重新运行 / 卸载定时器、订阅、事件监听

带依赖的请求：userId 变了才重新拉取

实战：拉取帖子列表（含 loading / error）

配套示例：useEffect-dependencies

教材文件夹里的 useEffect-dependencies/ 是可直接用浏览器打开的 CDN 示例：点击按钮改变 userId， effect 因为依赖了 userId 而重新运行，去拉取对应用户。

常见坑：无限循环

🚨 为什么会死循环
没有依赖数组 → 每次渲染后都执行 → 里面又调用 setCount 改变 state → 再次渲染 → 无限循环。 解决办法：补上依赖数组，并确认副作用不会无条件地修改自己所依赖的状态。

最佳实践

  1. 依赖数组里写全 effect 用到的所有会变化的值
  2. 用 ESLint 插件 react-hooks/exhaustive-deps 检查漏写的依赖
  3. 订阅、定时器、事件监听一定要清理
  4. 用多个 useEffect 拆分不同关注点，不要全塞进一个

  • 订阅、定时器、监听器必须清理；不同关注点用不同的 effect

Context 用来在组件树中共享「类全局」的数据，不必一层层传 props。它常与 useState 搭配： 顶层用 state 存数据，再用 Provider 把数据（以及修改函数）发下去。

进阶：一个 Context 共享多个值

多个 Context 与 children

🔑 children 到底是什么
把 Provider 想成礼品盒：它负责把「礼物」（context 数据）发给盒子里的一切，而 {children} 就是你放进去的东西。 它是一个占位符，告诉 React「把写在组件标签之间的内容渲染到这里」，于是无论嵌套多深，里面的组件都能拿到这份数据。

自定义 Hook 模式（推荐）

性能与最佳实践

  • Provider value 变化时，所有消费该 context 的组件都会重新渲染
  • 按更新频率拆分 context（稳定的放一起，频繁变化的单独放）
  • value 是对象时用 useMemo 稳定引用（见下一节）
  • 一个 context 只负责一类关注点，别搞一个巨大的 AppContext
  • 自定义 Hook 里做 if (!context) throw 的校验，避免拿到 undefined

常见疑问

Q：Context 能共享给兄弟组件吗？
A：能。只要两个兄弟都在同一个 Provider 内部，就能读到同一份数据。

Q：Context 能取代所有 props 吗？
A：不能。父子之间的局部通信用 props；多层 / 多组件都需要同一份数据时才用 context。

Q：所有东西都放进 context 好吗？
A：不好。context 只放真正需要共享的部分。

6useMemo：缓存计算结果

用 useMemo 可以避免一次昂贵的计算在无关的重渲染中被反复执行。

学习目标

  1. 说清楚 useMemo 做了什么
  2. 理解记忆化（memoization）中的依赖数组
  3. 能写出一个「昂贵计算」的演示
  4. 能把同样的思路用到真实场景（Context 的 provider value）

它到底是什么

useMemo 保存一个计算出来的值，只有在依赖变化时才重新计算：

  1. 首次渲染：执行函数并缓存结果
  2. 后续渲染：依赖没变就复用缓存值
  3. 依赖变了：重新计算并更新缓存

课堂 Demo：两个计数器

组件里有 count（频繁变化）和 otherCount（与之无关）两个状态，把昂贵计算只挂在 count 上。

  • 点 Other + 1：组件重渲染，但昂贵计算不会再跑（控制台没有新日志）
  • 点 Count + 1：依赖变了，昂贵计算重新执行

与 Context 的连接

原因：Provider 的 value 是个对象，不用 useMemo 时每次渲染都会生成新的引用， 稳定的引用可以减少下游不必要的更新。

⚠️ 常见错误
  1. 漏写依赖 → 拿到过期（stale）的值
  2. 给很小 / 很便宜的计算也套上 useMemo → 反而更慢更复杂
  3. 以为 useMemo 能阻止组件重渲染 → 它只记忆值，不记忆组件（组件用 React.memo）

7useRef：记住值，但不触发渲染

useRef 创建一个跨渲染保持不变的可变引用。和 state 不同，修改 ref.current 不会触发重新渲染。它常用于：直接访问 DOM 元素、保存可变值、保存不需要驱动渲染的数据。

useRef vs useState（先跑一遍这个例子）

  • 点 Increment Ref：refCount.current 在涨，但屏幕上的数字不动
  • 点 Increment State：立刻重渲染，屏幕更新
  • 先点几次 ref 再点 state：重渲染后 ref 的最新值会显示出来 —— 值一直都在，只是之前没重画
useRefuseState
跨渲染保留值是是
变化时触发渲染否是
取值方式ref.current直接用变量
可变性可变（mutable）应视为不可变，用 setter 替换
适合DOM 引用、timer id、计数器驱动界面的 UI 状态

✅ 该做
  • 用 ref 做 DOM 操作：聚焦、滚动、测量
  • 用 ref 存不需要驱动渲染的可变值（计数器、timer id、第三方库实例）
  • 给 ref 一个合理的初始值：DOM 用 null，数字用 0
🚨 别这样做
  • 别用 ref 存「应该驱动界面更新」的值 —— 界面不会刷新
  • 别在渲染过程中读写 ref.current（初始化除外），应放到 useEffect / 事件处理里
  • 别忘记判空：if (inputRef.current) inputRef.current.focus();
🔑 一句话总结
值变了要更新屏幕 → 用 useState；只是想记住这个值（或要拿到 DOM 元素）→ 用 useRef。

五个 Hook 的签名

Hook写法要点
useStateconst [x, setX] = useState(init)用 setter 更新；对象/数组要换新引用；连续更新用 setX(v => …)
useEffectuseEffect(fn, deps)fn 可返回清理函数；deps 决定时机
useContextconst v = useContext(SomeCtx)配合 createContext() 与 <Ctx.Provider value={…}>
useMemoconst v = useMemo(() => calc(), deps)只记忆值；别给廉价计算加它
useRefconst r = useRef(init)读写 r.current，不触发渲染

依赖数组速记

写法含义
useEffect(fn)每次渲染后都跑
useMemo(fn)（不写 deps）每次渲染都重算，等于没优化
…(fn, [])只在首次（挂载）时跑 / 算一次
…(fn, [a, b])a 或 b 变化时跑 / 重算
